# Как помочь BudetOffer

Этот репозиторий содержит исходники расширения Chrome, самостоятельную сборку, готовые версии, инструкции и публичные обращения пользователей.

## Сообщить об ошибке

1. Проверьте [решение проблем](docs/troubleshooting.md) и [последний релиз](https://github.com/poizoncc/budetoffer/releases/latest).
2. Посмотрите [открытые Issues](https://github.com/poizoncc/budetoffer/issues), чтобы не создавать дубликат.
3. Создайте обращение по форме **«Ошибка»**. Укажите версию расширения и Chrome, шаги, ожидаемый результат и фактическую ошибку.

Публикуйте только данные, нужные для воспроизведения. На скриншотах скройте личные контакты и содержимое резюме. Не прикладывайте коды входа, пароли, cookies, токены или данные хранилища расширения.

## Предложить улучшение

Используйте форму **«Предложение»** в Issues. Опишите задачу, текущую трудность и результат, который хотите получить. Пример сценария полезнее списка интерфейсных пожеланий.

## Исправить документацию

Отправьте Pull Request с небольшим, самостоятельным изменением. Укажите, какое место было непонятным, и сверьте названия кнопок с актуальной версией расширения или кабинета. Не добавляйте реальные резюме и личные данные даже в примеры.

## Изменить расширение

1. Ознакомьтесь с [составом исходников и потоком данных](docs/source.md). Сервер кабинета не входит в этот репозиторий.
2. Установите Node.js 22.12 или новее и выполните `npm ci --ignore-scripts --registry=https://registry.npmjs.org`.
3. Внесите небольшое самостоятельное изменение. Сохраните ограничения доменов, проверки владельца резюме и аккаунта HH, сроки заданий и отдельное разрешение на отправку отклика.
4. Выполните проверки и сборку:

   ```bash
   npm run check
   npm test
   npm run build
   ```

5. Проверьте папку `build/budetoffer-chrome` как распакованное расширение на собственном тестовом аккаунте. Не отправляйте отклик и не изменяйте данные HH, если это не требуется для вашего изменения.
6. В Pull Request опишите проблему, изменение и выполненные проверки. Добавляйте только синтетические тестовые данные.

`package-lock.json` фиксирует зависимости из публичного npm. Включайте его изменение при обновлении зависимостей; не добавляйте `.npmrc` с авторизацией, `.env`, профили браузера или содержимое `chrome.storage`.

Каталоги `build` и `node_modules` не коммитятся. Готовая версия в `distribution` меняется только при подготовке нового релиза; опубликованные версии и теги сохраняются.

Вопросы уязвимостей рассматриваются отдельно: [как безопасно сообщить о проблеме](SECURITY.md).
