# Исходники расширения и границы доступа

Исходники позволяют проверить, что расширение делает в Chrome, какие данные передаёт кабинету и как получается устанавливаемая папка. Они опубликованы отдельно от серверной части BudetOffer: база данных, кабинет, генерация текстов и серверные проверки доступа в этот репозиторий не входят.

## Состав

Общий модуль [`packages/ewans/src/index.ts`](../packages/ewans/src/index.ts), добавленный в 0.2.8, содержит единый каталог сообщений для worker и popup. Сборка помещает его скомпилированный код в `shared/ewans.js`. Модуль не импортирует серверные зависимости. [Контракт и проверка сообщений EWANS](ewans.md).

## Как проходят задания и данные

1. Пользователь получает код в расширении и подтверждает его в своём кабинете. После подтверждения расширение получает токен устройства для связи с кабинетом.
2. Расширение сохраняет токен и состояние в `chrome.storage.local`. Токен создаётся при подключении; в исходниках и ZIP нет заранее выданных учётных данных. Хранилище расширения ограничено доверенными контекстами Chrome.
3. Пока Chrome открыт, фоновый обработчик проверяет подключение и запрашивает задания кабинета. Полученное задание содержит конкретный вид операции, целевой объект и срок действия.
4. Для работы с HH расширение использует текущий вход пользователя на сайте. Оно открывает собственные фоновые вкладки, проверяет аккаунт до и после чтения и возвращает кабинету результат задания.

Начиная с 0.2.11, исполнитель различает завершённый переход и ещё загружающуюся страницу. Chrome может возвращать прежний адрес `url`, пока `pendingUrl` указывает на запрошенную страницу. В этот момент чтение не начинается. Допустим переход на тот же ресурс HH с тем же путём и параметрами, включая региональный поддомен; другой адрес останавливает задание. Ожидание ограничено 20 секундами и сроком задания. Основание: [описание `Tab.url` и `Tab.pendingUrl` в API Chrome](https://developer.chrome.com/docs/extensions/reference/api/tabs#type-Tab).

Результат задания, в том числе прочитанные данные резюме, может временно сохраняться в локальном хранилище расширения до подтверждения доставки. После подтверждения приёма сервером контрольная запись очищается. Неподтверждённая отправка отклика сохраняет состояние для сверки результата, чтобы не отправить его повторно.

| Действие                    | Что может попасть в результат для кабинета                                                                    |
| --------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Проверка резюме             | Идентификаторы выбранного резюме и подтверждение его принадлежности текущему аккаунту.                        |
| Чтение резюме для импорта   | Заголовок, блок «О себе» и выбранные ключевые навыки поддерживаемой страницы.                                 |
| Поиск и проверка вакансий   | Идентификатор вакансии, заголовок, компания и текст описания.                                                 |
| Чтение результатов откликов | Идентификаторы связанных записей и распознанные этапы или результаты.                                         |
| Отправка отклика            | Выбранное резюме, подготовленное письмо и подтверждение результата; требуется отдельное серверное разрешение. |

Пароль HH вводится только на самом HH. Расширение не запрашивает разрешение Chrome `cookies`. Запросы к серверу BudetOffer используют токен устройства и `credentials: "omit"`; cookies кабинета к ним не добавляются. Cookies входа HH используются самим браузером при открытии страниц HH.

Исполнитель отправки отклика присутствует в исходниках. Перед отправкой он проверяет текущий аккаунт, владельца и выбор резюме, состояние формы и историю откликов, затем получает разрешение сервера. Подключение устройства и наличие кода отправки сами по себе не отправляют отклик. Доступность этой операции определяется сервером кабинета; его реализация не является частью этой публикации.

## Разрешения и сборочная конфигурация

Публичная сборка ограничивает `host_permissions` адресом `https://my.budetoffer.ru` и страницами `https://hh.ru` / `https://*.hh.ru`. Она использует `activeTab`, `storage`, `scripting` и `alarms`.

Начиная с 0.2.9 публичные исходники по умолчанию настроены на `https://my.budetoffer.ru`: manifest, адреса подключения и ссылки на документы согласованы с публичным релизом. Worker и popup читают настройки через `shared/config.ts`; BFF/API URLs вычисляются из выбранного назначения, а сообщение об ошибке подключения — из EWANS.

Сборщик может выбрать другой проверенный HTTPS-кабинет: он заменяет `shared/destinations.js`, и вычисляемая конфигурация следует этому адресу. Локальная упаковка явно включает отдельный manifest с loopback-разрешениями и `SERVER_ORIGIN = null`. Наличие локального fallback в исходнике не добавляет разрешение к нему в публичную сборку. Проверяйте итоговые `manifest.json`, `shared/config.js` и `shared/destinations.js`.

В 0.2.6 собственные исходники фонового обработчика, адаптеров HH, контроллера, общих модулей и сборочных скриптов перенесены на TypeScript; интерфейс использует TypeScript/TSX и CSS. Это изменение языка не означало полного соблюдения стандартов QRKO: отдельной проверки типов тестов и проверок архитектурных границ в той версии не было.

В 0.2.7 добавлены разделённые TypeScript-конфигурации runtime, popup, Node-инструментов и тестов, контроль границ импортов, единый формат Prettier и правила React Hooks. [Правила и подтверждённые основания QRKO](standards.md).

Сборщик сначала проверяет runtime-модули, затем компилирует `.ts` в `.js` и переписывает локальные импорты для Chrome. Интерфейс собирается в локальные файлы расширения. Функции чтения HH, которые Chrome сериализует для выполнения в изолированной странице, содержат свои runtime-помощники и не зависят от замыкания модуля. Установка распакованного расширения не включает автоматическое обновление: пользователь заменяет файлы вручную.

## Сверка исходников и устанавливаемого пакета

При проверке 2026-10-15 сравнивались фоновые обработчики, адаптеры HH, общие модули, popup, сборщик, manifest, ссылки на документы и файлы ZIP. В публичных исходниках нет параллельных старых JavaScript-версий runtime: устанавливаемые `.js` получаются из TypeScript при сборке.

В закрытом рабочем проекте сохраняется отдельный Local-режим. Его исходные manifest, `shared/destinations.ts` и `shared/onboarding.ts` содержат loopback-настройки; публичные исходники этих файлов используют `my.budetoffer.ru`. Различие `popup.css` ограничивает сборку стилей опубликованным набором компонентов. Общий runtime, страница popup, EWANS и сборщик сверяются отдельно от этих настроек окружения.

Loopback-адреса в Local-адаптере и Vite dev server нужны для разработки. Они не добавляют локальные host permissions в Server-пакет: режим выбирается при упаковке, а готовый manifest и назначения проверяются в тестах. Даты согласий и исторические номера исправлений в документации обозначают версию соответствующего контракта или изменения.

Версия условий хранится в `shared/onboarding.ts`: упаковщик использует её при выпуске модуля для выбранного кабинета, а popup отправляет версию, которую сообщил worker. Минимальная версия Chrome берётся из manifest для инструкции установки и целевой платформы Vite. Так изменение одной настройки не оставляет второй устаревший литерал в другом файле.

Загрузка из кабинета закреплена за официальным релизным ZIP: перед раздачей проверяются версия, размер и SHA-256. Сборка самого кабинета использует проверенный архив вместо повторной компиляции расширения из другого окружения. Подготовка новой версии расширения по-прежнему выполняется самостоятельной сборкой этого публичного репозитория.

Связь конкретного коммита с релизом подтверждает CI: он собирает исходники и побайтно сравнивает ZIP, `SHA256SUMS` и `release.json` с `distribution`. [Инструкция выпуска](releasing.md) использует номер из `package.json`, чтобы команды проверки и тегирования не оставались привязаны к старому релизу.

## Самостоятельная сборка

Нужны Node.js 22.19 или новее и npm; CI использует Node.js 24. Зависимости фиксирует `package-lock.json`, они загружаются из публичного npm. Учётная запись BudetOffer, данные HH и секреты для сборки не нужны.

```bash
npm ci --ignore-scripts --registry=https://registry.npmjs.org
npm run format:check
npm run lint
npm run check
npm test
npm run build
```

Prettier 3.9.9 проверяет формат отдельно от ESLint 9/neostandard. Линтер запрещает вложенные тернарные операторы, `any` и подавления и проверяет React Hooks с зависимостями effects. `npm run check` включает строгие типы runtime, popup, Node-скриптов, **Node- и UI-тестов**, а также `check:boundaries` для импортов и SHA-256 оригинальных vendored-файлов. Узкие команды перечислены в [стандартах](standards.md).

Результат находится в `build/budetoffer-chrome` и `build/budetoffer-chrome.zip`; рядом создаются `SHA256SUMS` и `release.json`. Установить можно именно папку с итоговым `manifest.json`, как описано в [инструкции](install.md). Папки исходников и автоматический архив GitHub **Source code** напрямую в Chrome не загружаются.

ZIP, `SHA256SUMS` и `release.json` побайтно совпали с `distribution`. Новые проверки воспроизводят переходы Chrome и чтение полей резюме для импорта на синтетических страницах; это не проверка полного сценария реального аккаунта HH. ## Связь исходников с релизами

Начиная с версии **0.2.5**, исходники и самостоятельная сборка публикуются вместе с расширением. В публичную сборку включены используемые компоненты интерфейса; стили собираются только по этому набору файлов. Зависимости и правила упаковки доступны в том же репозитории.

Релиз [v0.2.4](https://github.com/poizoncc/budetoffer/releases/tag/v0.2.4) был опубликован до появления исходников в этом репозитории. Его тег указывает на коммит [`e689e7e`](https://github.com/poizoncc/budetoffer/commit/e689e7e47e93183c12fe834b5b17fde3c71a9f8c), содержащий готовый пакет и инструкции. Мы сохраняем этот тег и вложения без замены.

Сборка 0.2.5 не заявляется побайтной копией исторического ZIP 0.2.4: изменились номер версии и состав источников генерации CSS. В автоматическом архиве **Source code** старого тега по-прежнему находятся файлы, опубликованные с тем тегом. Для проверки новой версии выбирайте её тег, а для установки — вложение `budetoffer-chrome.zip` соответствующего релиза.

При сравнении пакетов 0.2.4 и 0.2.5 совпали 35 файлов: исполнители, обработчики HH, контроллер, общие модули, изображения, шрифты и тексты лицензий. Различаются manifest, HTML и собранные файлы интерфейса. JavaScript интерфейса совпадает после нормализации изменившихся имён файлов ресурсов; CSS изменился из-за ограничения набора сканируемых исходников.
