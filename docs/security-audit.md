## Какие данные остаются только во время работы

После подтверждения кода сервер выдаёт расширению токен устройства. Он сохраняется в `chrome.storage.local`, вместе с состоянием входа и выполняемого задания. В публикуемые файлы он не встроен.

Результаты заданий, включая прочитанные данные резюме, могут временно храниться в контрольной записи до подтверждения приёма сервером. После подтверждения запись очищается. Состояние неопределённого результата отправки сохраняется для сверки и защиты от повторного отклика.

Пароль HH вводится на самом HH. Расширение не запрашивает разрешение `cookies`; запросы в кабинет передают токен устройства с `credentials: "omit"`. Браузер использует вход в HH при открытии его страниц. Поток данных и список действий описаны в [документе об исходниках](source.md).

## Как повторить проверку

Нужны Python 3 и **Gitleaks 8.30.1** в `PATH`. Скрипт проверяет версию сканера и завершает работу с ошибкой, если сканер отсутствует или проверка не завершилась.

```bash
python3 scripts/check-secrets.py
python3 -m unittest discover -s tests -p 'test_check_secrets.py'
gitleaks git --log-opts=--all --redact=100
```

Первая команда проверяет все отслеживаемые Git файлы и содержимое архивов. При подготовке нового коммита добавьте `--include-untracked`, чтобы включить ещё не добавленные и не игнорируемые файлы. Скрипт также отклоняет закрытые пути, символьные ссылки, повреждённые, зашифрованные и слишком глубокие архивы; он не пропускает их молча.

Список файлов ограничен содержимым этого репозитория. Игнорируемые `node_modules` и `build` не входят в публикацию; устанавливаемый ZIP проверяется из `distribution`.

Проверки по шаблонам не доказывают отсутствие любых неизвестных форматов секретов. Если вы заметили раскрытые данные или уязвимость, используйте [непубличный порядок сообщения](../SECURITY.md), не копируя секрет в Issues.
