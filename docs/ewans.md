# Как устроены сообщения EWANS

Актуально для версии **0.2.9**, 2026-10-15.

Ошибки подключения Chrome и выполнения заданий получают стабильный код
`BO-COMP-xxx`, понятное объяснение и следующий шаг. Код помогает сообщить о
проблеме без передачи резюме, cookies, кода входа или содержимого storage.

## Один каталог для расширения и кабинета

Канонический каталог находится в
[`packages/ewans/src/index.ts`](../packages/ewans/src/index.ts). В нём 45 записей
с постоянными кодами; новые записи не должны менять номера существующих.
Worker, popup и серверный адаптер используют один контракт.

Это адаптация шестиполевого контракта QRKO EWANS для BudetOffer. Общий модуль не
импортирует NestJS, Fastify, Chrome API, React или Node.js API. Серверные
зависимости не попадают в расширение, а самостоятельная сборка не требует
исходников BFF. Сам BFF в этот публичный репозиторий не входит.

| Поле         | Значение                                                                        |
| ------------ | ------------------------------------------------------------------------------- |
| `code`       | Постоянный код поддержки, например `BO-COMP-001`.                               |
| `message`    | Короткое объяснение из локального каталога.                                     |
| `status`     | Категория сообщения: `error`, `warning`, `alert`, `notification` или `success`. |
| `group`      | Группа `COMPANION`.                                                             |
| `key`        | Машинный ключ, например `invalid_pairing`.                                      |
| `httpStatus` | HTTP-код, соответствующий этой записи.                                          |

Следующий шаг хранится рядом с записью каталога и добавляется при отображении.
Это не седьмое поле передаваемого дескриптора. Пользователь видит объяснение,
действие и код в скобках.

## Ошибки HTTP и сообщения Chrome

В API кабинета ошибка остаётся `application/problem+json`: верхнее поле
`status` содержит числовой HTTP-код. Дескриптор добавляется в поле `ewans`,
поэтому его текстовая категория `status` не заменяет HTTP-статус:

```json
{
  "type": "about:blank",
  "title": "invalid_pairing",
  "status": 400,
  "code": "invalid_pairing",
  "ewans": {
    "code": "BO-COMP-001",
    "message": "Код подключения введён неверно.",
    "status": "error",
    "group": "COMPANION",
    "key": "invalid_pairing",
    "httpStatus": 400
  }
}
```

Существующие успешные ответы API сохраняют свой формат. Worker может передать
`ewans` вместе с сообщением о фоновой ошибке и подтверждённым состоянием
подключения. Такая ошибка сама по себе не превращает подключённое устройство в
неподключённое.

Сервер предоставляет общий каталог через `GET /api/v1/companion/ewans`.
Запрос проходит существующие проверки gateway; маршрут не создаёт отдельного
способа обхода входа или прав. Доступность сервера не нужна для сборки
расширения: каталог уже включён в исходники.

Область внедрения — ошибки companion. Остальные API продукта сохраняют
существующий формат. Общий BFF-клиент кабинета умеет прочитать необязательное
поле `ewans`, сохраняя прежнюю обработку ответов без него.

## Проверка данных и полномочий

Перед отображением проверяются все шесть полей: код должен существовать в
каталоге, остальные значения — совпадать с этой записью. Для HTTP-ответа также
проверяется соответствие реальному статусу ответа. Подменённый текст,
неизвестный код, лишние поля и некорректный дескриптор не становятся сообщением
пользователю. Используется безопасное объяснение из каталога; произвольные
внутренние исключения и диагностические строки не выводятся.

Старые версии worker и сервера поддерживаются: известные машинные ключи
сопоставляются с каталогом, а popup сохраняет предусмотренные локальные
сообщения старого worker. Неизвестные строки заменяются безопасной подсказкой.

EWANS описывает проблему и не разрешает действие. Проверки аккаунта,
принадлежности резюме, согласий, срока задания и отдельного разрешения на
отправку выполняются прежним протоколом. Метаданные `retrySafe` и
`outcomeUnknown` также сохраняют свой смысл; наличие кода не запускает
автоматическое повторение действия.

В фоновом исполнении HTTP `401` по-прежнему отзывает локальное подключение.
HTTP `403`, в том числе отсутствие доступа к автоматическому действию, не
удаляет привязку Chrome. Дескриптор или его категория не могут изменить это
решение.

## Что проверяет сборка

Из одного исходного модуля сборка выпускает `shared/ewans.js` внутри ZIP.
Перенос runtime-модулей меняет только спецификаторы импортов через AST.
Тела функций, которые Chrome сериализует и выполняет на страницах HH,
сохраняются без такого переписывания.

Unit-тесты проверяют каталог, совместимость, отклонение подделанных данных и
сохранение состояния подключения. Интеграционный тест архива проверяет наличие
единственного модуля EWANS, соответствие каноническому исходнику, разрешение
импортов внутри ZIP и выполнение скомпилированного транспорта. Проверки не
требуют аккаунта HH и не означают ручную проверку полного сценария на реальном
HH.
